# AISI0031: @featureInstalled with an unknown feature

**Severity:** warning

`@featureInstalled('PX.Objects.CS.FeaturesSet+X')` shows a class only while feature X is on. A name that isn't a
property of the site's `FeaturesSet` (or an extension of it) is never on, so the class never shows.

## Wrong

```ts
@featureInstalled('PX.Objects.CS.FeaturesSet+Multicurency')
```

## Right

```ts
@featureInstalled('PX.Objects.CS.FeaturesSet+Multicurrency')
```

## Where the answer comes from

This rule reads the compiled assemblies in the site's `Bin` folder (the one beside the `FrontendSources` folder
the file sits in) without loading them. It stays quiet when the file isn't in a site, when the Bin can't be read,
and when something it would need, such as a base class in an assembly that isn't in `Bin`, can't be seen.

Customisation code published as source goes to `App_RuntimeCode` rather than `Bin`. Any name that appears in a
`.cs` file there is taken as declared. So are the names Acumatica adds at run time that this rule knows about
(`Process` and `ProcessAll` from processing views; `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`).
Anything else added in code at run time, such as `Actions.Add` or a field added in `FieldSelecting`, will be
reported. Suppress those lines, as shown below.

## Source

- [UI Customization Development: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_Customization_GeneralInfo.md): "Optional: In the parameter of the `featureInstalled` decorator, specify the feature for which the extension should be available."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0031`. For the whole file: `// muilint-disable AISI0031`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0031.severity = none
```
