# AISI0010: Added field is not Usr-prefixed

**Severity:** suggestion

Custom DAC fields carry the `Usr` prefix, so a `<field>` your extension adds (it, or a container around it, has
`after`, `before`, `append`, `prepend` or `replace`) without one is worth a second look. Often it's fine: you're moving
a stock field to a new spot. When the stock screen is available and already has that field, MuiLint recognises the
move and says nothing.

Only extension files are checked; a screen of your own has no reason to use the prefix. `View.UsrField` names are
checked on the part after the dot.

## Wrong

```html
<field name="DeliveryNote" after="[name='LocationID']"></field>
```

## Right

```html
<field name="UsrDeliveryNote" after="[name='LocationID']"></field>
```

## Turning it off

Once, above the offending line:

```html
<!-- muilint-disable-next-line AISI0010 -->
```

For the whole file, anywhere in it: `<!-- muilint-disable AISI0010 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0010.severity = none
```
