# AISI0019: qp-include parameters

**Severity:** warning

A reusable UI definition declares its parameters in `<qp-include-parameters>`. A parameter marked `.required` has to
be given on every `<qp-include>` of that file. An attribute the included file doesn't declare is reported too,
because it is usually a typo of a parameter it does declare (`capton=` for `caption=`), whose value then never
arrives. That second half is MuiLint's inference rather than a quote from the docs.

`url`, `id`, `class`, `style`, `slot`, the merge operators (`after`, `before`, ...), `data-*`, `aria-*` and anything with
a dot in its name (`view.bind`, ...) are never reported as undeclared. An included file that declares no parameters
isn't checked at all.

## Wrong

```html
<!-- form-address.html declares: <qp-include-parameters id.required address-view.required caption="Address"> -->
<template>
  <qp-include url="../../../common/forms/form-address/form-address.html" id="formA" capton="Ship to"></qp-include>
</template>
```

## Right

```html
<template>
  <qp-include url="../../../common/forms/form-address/form-address.html" id="formA"
    address-view="AddressCurrent" caption="Ship to"></qp-include>
</template>
```

## Source

- [Reusing of UI Definitions: Reusable UI Definitions with Parameters](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_UIDefinitionReuse_Params.md): "When this modifier is specified, a developer must provide a value for the parameter while inserting the reusable UI definition in a particular form."

## Turning it off

Once, above the offending line: `<!-- muilint-disable-next-line AISI0019 -->`. For the whole file, anywhere in it:
`<!-- muilint-disable AISI0019 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0019.severity = none
```
