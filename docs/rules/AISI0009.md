# AISI0009: Selector target not in stock HTML

**Severity:** warning

A merge selector names a `[name='X']` or `#id` that isn't in the stock screen, in any other extension of it, or
above in this file. The Modern UI build fails on a selector that matches nothing. Usually it's a typo.

Anchoring on something this file adds earlier is fine: elements apply in order, and Acumatica's own training chains
`UsrRepairItemType` after `UsrRepairItem` that way.

This needs the stock screen, so it runs in the CLI, the Action and the VSIX, not in the Roslyn analyser.

## Wrong

```html
<field name="UsrWeight" before="[name='OrderDat']"></field>
```

## Right

```html
<field name="UsrWeight" before="[name='OrderDate']"></field>
```

## Source

- [Reusing of UI Definitions: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_UIDefinitionReuse_GeneralInfo.md): "If no element satisfies the CSS selector, the build process fails."
- [Updating a Customization Project for the Modern UI: To Convert a Customized Form](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_Customization_Convert_Activity_CustomizedForm.md): anchors `after="#fsItemDefaults-General FIELD[name='UsrRepairItem']"` on a field the same file adds.

## Turning it off

Once, above the offending line: `<!-- muilint-disable-next-line AISI0009 -->`. For the whole file, anywhere in it:
`<!-- muilint-disable AISI0009 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0009.severity = none
```
