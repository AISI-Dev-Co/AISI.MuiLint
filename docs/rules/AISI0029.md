# AISI0029: Field not on the view's DAC

**Severity:** warning

A `PXFieldState` on a view class that the DAC behind the view doesn't have, its base DACs and cache extensions
included. When one view class serves several views, a field is fine if any of their DACs has it. Fields of joined
DACs (`Customer__AcctName`) are skipped, as are view classes behind a view the graph doesn't have or whose DAC can't
be read.

## Wrong

```ts
export class RSSVWorkOrder extends PXView {
    OrderNbr: PXFieldState;
    Priorty: PXFieldState;
}
```

## Right

```ts
export class RSSVWorkOrder extends PXView {
    OrderNbr: PXFieldState;
    Priority: PXFieldState;
}
```

## Where the answer comes from

This rule reads the compiled assemblies in the site's `Bin` folder (the one beside the `FrontendSources` folder
the file sits in) without loading them. It stays quiet when the file isn't in a site, when the Bin can't be read,
and when something it would need, such as a base class in an assembly that isn't in `Bin`, can't be seen.

Customisation code published as source goes to `App_RuntimeCode` rather than `Bin`. Any name that appears in a
`.cs` file there is taken as declared. So are the names Acumatica adds at run time that this rule knows about
(`Process` and `ProcessAll` from processing views; `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`).
Anything else added in code at run time, such as `Actions.Add` or a field added in `FieldSelecting`, will be
reported. Suppress those lines, as shown below.

## Source

- [UI Definition in HTML and TypeScript: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_UIDefinition_GeneralInfo.md): "In each view class, you specify the properties for all data fields of the data view that you want to be able to show or use in the UI, as shown below. You use the name of the data field as the property name."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0029`. For the whole file: `// muilint-disable AISI0029`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0029.severity = none
```
