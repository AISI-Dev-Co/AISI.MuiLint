# AISI0027: graphType not in the site

**Severity:** warning

The `graphType` in `@graphInfo` names a graph that no assembly in the site's `Bin` defines: usually a typo, a wrong
namespace, or a customisation that hasn't been built yet. A nested graph may be written with `.` or `+`.

## Wrong

```ts
@graphInfo({ graphType: "PhoneRepairShop.RSSVWorkOrderEnrty", primaryView: "WorkOrders" })
```

## Right

```ts
@graphInfo({ graphType: "PhoneRepairShop.RSSVWorkOrderEntry", primaryView: "WorkOrders" })
```

## Where the answer comes from

This rule reads the compiled assemblies in the site's `Bin` folder (the one beside the `FrontendSources` folder
the file sits in) without loading them. It stays quiet when the file isn't in a site, when the Bin can't be read,
and when something it would need, such as a base class in an assembly that isn't in `Bin`, can't be seen.

Customisation code published as source goes to `App_RuntimeCode` rather than `Bin`. Any name that appears in a
`.cs` file there is taken as declared. So are the names Acumatica adds at run time that this rule knows about
(`Process` and `ProcessAll` from processing views; `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`).
Anything else added in code at run time, such as `Actions.Add` or a field added in `FieldSelecting`, will be
reported. Suppress those lines, as shown below.

## Source

- [Data Entry Form: To Create the UI of a Data Entry Form](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_DataEntryScreen_Activity_CreateFromScratch.md): "For the screen class, add the graphInfo decorator, and specify the graph and the primary view of the form in the decorator properties."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0027`. For the whole file: `// muilint-disable AISI0027`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0027.severity = none
```
