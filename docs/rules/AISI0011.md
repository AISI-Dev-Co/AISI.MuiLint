# AISI0011: Binding not declared in the screen's TypeScript

**Severity:** warning

`view.bind`, a field's `name`, or a `qp-button`'s `state.bind` refers to something the screen's TypeScript doesn't
declare. MuiLint reads the screen's `.ts`, what it imports, and every extension of the screen: the stock ones,
`development/screens`, and `customizationScreens`. An extension that is only HTML is checked against the screen
those make.

The view around a field is the nearest `view.bind`, `qp-panel` id or `<using view="...">`, as AcuMate reads it. On
anything but a `qp-button`, `state.bind` names a field, not an action, and isn't checked.

## Wrong

```html
<qp-fieldset id="fsAISI" after="#fsColumnA-Order" view.bind="Document">
  <field name="UsrPriorty"></field>
</qp-fieldset>
```

The lightbulb adds `UsrPriorty: PXFieldState` to an extension of the view's class, creating the `.ts` if the extension
has none.

## Source

- [UI Definition in HTML and TypeScript: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_UIDefinition_GeneralInfo.md): "In each view class, you specify the properties for all data fields of the data view that you want to be able to show or use in the UI".
- [Button: Configuration](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDevRef_Button_Configuration.md): a button's `state.bind` names "the action added in the screen class".

## Turning it off

Once, above the offending line: `<!-- muilint-disable-next-line AISI0011 -->`. For the whole file, anywhere in it:
`<!-- muilint-disable AISI0011 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0011.severity = none
```
