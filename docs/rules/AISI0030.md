# AISI0030: @linkCommand to an unknown action

**Severity:** warning

`@linkCommand("Action")` runs an action when the cell's link is clicked. An action the graph doesn't have makes a
link that does nothing.

## Wrong

```ts
@linkCommand("ViewAset") AssetID: PXFieldState;
```

## Right

```ts
@linkCommand("ViewAsset") AssetID: PXFieldState;
```

## Where the answer comes from

This rule reads the compiled assemblies in the site's `Bin` folder (the one beside the `FrontendSources` folder
the file sits in) without loading them. It stays quiet when the file isn't in a site, when the Bin can't be read,
and when something it would need, such as a base class in an assembly that isn't in `Bin`, can't be seen.

Customisation code published as source goes to `App_RuntimeCode` rather than `Bin`. Any name that appears in a
`.cs` file there is taken as declared. So are the names Acumatica adds at run time that this rule knows about
(`Process` and `ProcessAll` from processing views; `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`).
Anything else added in code at run time, such as `Actions.Add` or a field added in `FieldSelecting`, will be
reported. Suppress those lines, as shown below.

## Source

- [Button: Configuration](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDevRef_Button_Configuration.md): "To execute an action when a user clicks the link in a column of a grid, you specify the property with the name of the corresponding action in the screen class and use the linkCommand decorator for the column that displays the link."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0030`. For the whole file: `// muilint-disable AISI0030`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0030.severity = none
```
