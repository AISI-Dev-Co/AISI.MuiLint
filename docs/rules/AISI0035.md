# AISI0035: Extension method replaces a screen method

**Severity:** warning

A screen extension's methods are copied onto the screen class by name. If the screen, or another extension of it,
already has a method with that name, one of the two is replaced and nothing reports it. The screen's own code then
calls your method where it meant its own, or yours never runs.

Two event handlers with the same name are the exception: client-controls renames one and keeps both. A handler that
shares its name with a plain method is still reported.

The rule needs the screen's TypeScript, and sees every extension of the screen under `src/screens`,
`development/screens` and `customizationScreens`.

## Wrong

```ts
// SO301000 already has a refreshTotals()
export interface SO301000_AISI extends SO301000 {}
export class SO301000_AISI {
    refreshTotals() { }
}
```

## Right

```ts
export interface SO301000_AISI extends SO301000 {}
export class SO301000_AISI {
    refreshAisiTotals() { }
}
```

## Source

- `client-controls/descriptors/customization.js` in the site's `node_modules`. `applyScreenMixin`: "Reconstruct provided screen view model with all registered mixins by copying their property and method definitions to screen view model prototype". `applyMixins`: "It copies logic (methods, static properties) of provided mixins to the base class", with `Object.defineProperty(derivedCtor.prototype, name, ...)` for every method of the extension.
- None of the 486 screen extensions in Acumatica's own 26R1 screens reuses a method name of its screen.

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0035`. For the whole file: `// muilint-disable AISI0035`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0035.severity = none
```
