# AISI0018: Customizing tag not at the top level

**Severity:** error

A tag with `after`, `before`, `append`, `prepend`, `modify`, `remove` or `replace` has to sit directly in the
top-level `<template>`, not inside another element. To add fields to something, either give each field its own
`after`/`append`, or put them inside a `<template modify="#id">`.

Inside a `qp-include` that brings in part of a form is the one documented exception.

## Wrong

```html
<template>
  <qp-fieldset id="fsAISI" after="#fsColumnB-Order" view.bind="Document">
    <field name="UsrHandling" after="[name='OrderDate']"></field>
  </qp-fieldset>
</template>
```

## Right

```html
<template>
  <qp-fieldset id="fsAISI" after="#fsColumnB-Order" view.bind="Document"></qp-fieldset>
  <field append="#fsAISI" name="UsrHandling"></field>
</template>
```

## Source

- [UI Customization Development: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_Customization_GeneralInfo.md): "All tags that customize the original HTML code of an Acumatica ERP form must be located on the highest level of the extension layout—that is, in the template tag of the highest level."
- [UI Adjustments in HTML and TypeScript: HTML Examples](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_AdjustmentInExtension_HTML.md): says the same, and shows fields added inside `<template modify="#main">`.

## Turning it off

Once, above the offending line: `<!-- muilint-disable-next-line AISI0018 -->`. For the whole file, anywhere in it:
`<!-- muilint-disable AISI0018 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0018.severity = none
```
