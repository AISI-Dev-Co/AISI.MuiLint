# AISI0002: retired

This rule used to report an `after`/`before` selector anchored on a field the same extension file adds, on the theory
that the merge only sees stock HTML. That theory was wrong. The merge applies elements in order, so a later element
can anchor on one added above it. Acumatica's own training does exactly this:

```html
<field after="#fsItemDefaults-General [name='ItemType']" name="UsrRepairItem"></field>
<field after="#fsItemDefaults-General [name='UsrRepairItem']" name="UsrRepairItemType"></field>
```

It was removed in the release after 0.3.0, and the id won't be reused. An `.editorconfig` line or a
`muilint-disable` comment naming it does nothing now and can go.
