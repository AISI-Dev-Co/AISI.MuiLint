# AISI0034: Event handler takes another event's arguments

**Severity:** warning

Each event hands its handler its own arguments. A handler typed for a different event compiles against properties it
will never be given: `newValue` only exists on `ValueChangedHandlerArgs`, `rowIndex` on the row events, `selector` on
the CSS events.

| Event | Arguments |
| --- | --- |
| `ValueChanged` | `ValueChangedHandlerArgs` |
| `RowSelected`, `CurrentRowChanged` | `RowSelectedHandlerArgs` or `CurrentRowChangedHandlerArgs` (the same shape) |
| `GetRowCss` | `RowCssHandlerArgs` |
| `GetCellCss` | `CellCssHandlerArgs` |
| `CallbackCompleted` | `CallbackCompletedHandlerArgs` |

`any`, no parameter at all, and types of your own are left alone.

## Wrong

```ts
@handleEvent(CustomEventType.RowSelected, { view: "Document" })
onDocumentSelected(args: ValueChangedHandlerArgs) { }
```

## Right

```ts
@handleEvent(CustomEventType.RowSelected, { view: "Document" })
onDocumentSelected(args: RowSelectedHandlerArgs) { }
```

## Source

- `client-controls/descriptors/customization.d.ts` in the site's `node_modules`, on `EventHookDescriptor`: "The following arguments are used depending on the event type", followed by the list in the table above.
- [Activity 7.2.1: To Implement and Debug an Event Handler](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_HandlingEvents_DefineAndDebug_Activity.md) pairs `CustomEventType.GetRowCss` with `RowCssHandlerArgs`.

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0034`. For the whole file: `// muilint-disable AISI0034`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0034.severity = none
```
