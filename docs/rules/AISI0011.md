# AISI0011: Binding not declared in the screen's TypeScript

**Severity:** warning

Modern UI binds HTML to whatever the screen's TypeScript declares, and nothing else. A `<field>` whose name isn't on
the view class doesn't show up. A `view.bind` to a view that doesn't exist binds to nothing. Nothing tells you either
way until somebody opens the screen.

MuiLint reads the `.ts` next to your HTML and everything it imports (`./views`, `src/screens/...`), merges the
extension interfaces in, and then checks four things:

- `view.bind="X"`: the screen class has a member `X`.
- `<field name="F">`: the view of the nearest enclosing `view.bind` declares `F`, through its base classes and
  extensions. A field merged in with `after`/`before` and no view around it only has to be on *some* view.
  `name="View.Field"` names its own view.
- `state.bind="A"`: the screen class has a member `A`, usually `A: PXActionState`.
- `<qp-panel id="P">`: the screen has a view `P`, because a dialog's id is the view behind it.

It doesn't need a site. That also means it only knows what's in your files. When a view's class extends something
MuiLint can't open, or the screen class can't be found at all, it says nothing rather than guess. Elements with
`modify` or `remove` are skipped because they point at markup that already exists. So are `unbound` fields, which are
placeholders for custom content, and so are stock screens. Only the
CLI and the VSIX run it.

## Wrong

```ts
export interface SOOrderHeader_AISI extends SOOrderHeader {}
export class SOOrderHeader_AISI {
    UsrPriority: PXFieldState;
}
```

```html
<field name="UsrPriorty" after="[name='OrderDate']"></field>
```

## Right

```html
<field name="UsrPriority" after="[name='OrderDate']"></field>
```

## Turning it off

Once, above the offending line:

```html
<!-- muilint-disable-next-line AISI0011 -->
```

For the whole file, anywhere in it: `<!-- muilint-disable AISI0011 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0011.severity = none
```
