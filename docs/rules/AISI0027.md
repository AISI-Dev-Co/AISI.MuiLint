# AISI0027: graphType not in the site

**Severity:** warning

The `graphType` in `@graphInfo` names a graph no assembly in the site's `Bin` defines: usually a typo, a wrong
namespace, or a customisation that hasn't been built yet. A nested graph can be written with `.` or `+`.

## Wrong

```ts
@graphInfo({ graphType: "PhoneRepairShop.RSSVWorkOrderEnrty", primaryView: "WorkOrders" })
```

## Right

```ts
@graphInfo({ graphType: "PhoneRepairShop.RSSVWorkOrderEntry", primaryView: "WorkOrders" })
```

## Where the answer comes from

The compiled assemblies in the site's `Bin` (beside the file's `FrontendSources` folder), read without loading them.
The rule stays quiet when the file isn't in a site, `Bin` can't be read, or something it needs, such as a base class
in an assembly outside `Bin`, can't be seen.

Any name in a `.cs` file under `App_RuntimeCode`, where code published as source goes, counts as declared. So do
`Process` and `ProcessAll` from processing views and `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`.
Anything else added at run time, such as `Actions.Add` or a field added in `FieldSelecting`, is reported; suppress
those lines.

## Source

- [Data Entry Form: To Create the UI of a Data Entry Form](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_DataEntryScreen_Activity_CreateFromScratch.md): "For the screen class, add the graphInfo decorator, and specify the graph and the primary view of the form in the decorator properties."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0027`. For the whole file: `// muilint-disable AISI0027`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0027.severity = none
```
