# AISI0010: retired

This rule suggested a `Usr` prefix on fields an extension adds. The prefix is a database convention, not a Modern UI
one: Acumatica asks for it on columns you add to Acumatica's own tables, so they survive upgrades, and says your own
tables need no prefix. Its own extension example adds `ShowCuryDetail`, and extension tables and stock fields you
expose have no prefix either. See [Naming Conventions for Tables (DACs) and Columns (Fields)](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/StudioDeveloperGuide/DA__con_Table_Column_Naming_Conventions.md)
and [UI Customization Development: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_Customization_GeneralInfo.md).

The id won't be reused; a `muilint-disable` comment or `.editorconfig` line naming it does nothing now.
