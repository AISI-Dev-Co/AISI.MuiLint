# AISI0012: qp-* control without an id

**Severity:** suggestion

An id is how everything else finds a control. Other customizations target it with `after="#grid-Lines"`, and UI tests
look it up the same way. Leave it off and the control is fine today, but nobody can build on it later.

`qp-field`, `qp-label` and `qp-include` don't need one, and neither does an element with `modify` or `remove`, which
points at an element that already has its own id.

## Wrong

```html
<qp-grid after="#fsColumnB-Order" view.bind="Transactions"></qp-grid>
```

## Right

```html
<qp-grid id="grid-AISI-Transactions" after="#fsColumnB-Order" view.bind="Transactions"></qp-grid>
```

## Turning it off

Once, above the offending line:

```html
<!-- muilint-disable-next-line AISI0012 -->
```

For the whole file, anywhere in it: `<!-- muilint-disable AISI0012 -->`. For a whole folder, in `.editorconfig`:

```ini
[*.html]
dotnet_diagnostic.AISI0012.severity = none
```
