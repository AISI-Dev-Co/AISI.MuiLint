# AISI0002: retired

This rule reported an `after`/`before` selector anchored on a field the same extension file adds, assuming the merge
only sees stock HTML. It doesn't: elements apply in order, so a later one can anchor on one added above it.
Acumatica's own training does this:

```html
<field after="#fsItemDefaults-General [name='ItemType']" name="UsrRepairItem"></field>
<field after="#fsItemDefaults-General [name='UsrRepairItem']" name="UsrRepairItemType"></field>
```

Source: [Updating a Customization Project for the Modern UI: To Convert a Customized Form](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_Customization_Convert_Activity_CustomizedForm.md).

Removed in the release after 0.3.0; the id won't be reused. `.editorconfig` lines and `muilint-disable` comments
naming it do nothing now and can go.
