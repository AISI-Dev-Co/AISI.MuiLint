# AISI0032: @handleEvent without its view, field or column

**Severity:** warning

Every event except `CallbackCompleted` is raised for a view. `ValueChanged` is raised for one field of that view, and
`GetCellCss` for one column or for `allColumns: true`. A handler that leaves these out is attached to nothing.

Decorators whose second argument is a variable rather than an object literal are left alone.

## Wrong

```ts
@handleEvent(CustomEventType.ValueChanged, { view: "Document" })
onCustomerChanged(args: ValueChangedHandlerArgs) { }
```

## Right

```ts
@handleEvent(CustomEventType.ValueChanged, { view: "Document", field: "CustomerID" })
onCustomerChanged(args: ValueChangedHandlerArgs) { }
```

## Source

- [UI Events: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_HandlingEvents_GeneralInfo.md): "You use the handleEvent decorator to mark a handler of a runtime event for a specified view or field or with no relation to a view or field."
- [Activity 7.2.1: To Implement and Debug an Event Handler](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_HandlingEvents_DefineAndDebug_Activity.md): "in the second parameter, you've specified the view for which the event handler is intended."
- `client-controls/descriptors/customization-types.d.ts` in the site's `node_modules`: `view` is a required property of `BaseViewEventProps`, `field` of `ValueChangedProps`, and `CellCssProps` takes `column` or `allColumns: true`. Acumatica's own 26R1 screens have 256 view-event handlers, and none leaves one out.

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0032`. For the whole file: `// muilint-disable AISI0032`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0032.severity = none
```
