# AISI0028: View or action not on the graph

**Severity:** warning

A view (`createSingle`, `createCollection`) or action (`PXActionState`) on the screen class, or on an extension of it,
that the graph doesn't have, its graph extensions included. The front end matches them by name, so a misspelt one
binds to nothing. Names starting with `_` are skipped. If any part of the graph can't be read, nothing is reported.

## Wrong

```ts
export class RS301000 extends PXScreen {
    WorkOrder = createSingle(RSSVWorkOrder);   // the graph's view is WorkOrders
}
```

## Right

```ts
export class RS301000 extends PXScreen {
    WorkOrders = createSingle(RSSVWorkOrder);
}
```

## Where the answer comes from

The compiled assemblies in the site's `Bin` (beside the file's `FrontendSources` folder), read without loading them.
The rule stays quiet when the file isn't in a site, `Bin` can't be read, or something it needs, such as a base class
in an assembly outside `Bin`, can't be seen.

Any name in a `.cs` file under `App_RuntimeCode`, where code published as source goes, counts as declared. So do
`Process` and `ProcessAll` from processing views and `NoteText`, `NoteFiles` and `NotePopupText` from `PXNote`.
Anything else added at run time, such as `Actions.Add` or a field added in `FieldSelecting`, is reported; suppress
those lines.

## Source

- [Data Entry Form: To Create the UI of a Data Entry Form](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_DataEntryScreen_Activity_CreateFromScratch.md): "The names of the data view properties should be the same as those in the graph."

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0028`. For the whole file: `// muilint-disable AISI0028`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0028.severity = none
```
