# AISI0033: @handleEvent names an unknown field

**Severity:** warning

The `field` of a `ValueChanged` handler, or the `column` of a `GetCellCss` handler, isn't a field that the view's class
declares in TypeScript. Usually a typo, or a field that exists on the DAC but was never added to the view class.

The rule needs the screen's TypeScript. It stays quiet when the view's class can't be followed, for example when it
comes from a package.

## Wrong

```ts
@handleEvent(CustomEventType.GetCellCss, { view: "Transactions", column: "Quantity" })
getQuantityCss(args: CellCssHandlerArgs) { }
```

## Right

```ts
@handleEvent(CustomEventType.GetCellCss, { view: "Transactions", column: "OrderQty" })
getQuantityCss(args: CellCssHandlerArgs) { }
```

## Source

- `client-controls/descriptors/customization.d.ts` in the site's `node_modules`, on `handleEvent`: "All parameters of the decorator such as the event type and the view are validated. For example, for the `ValueChanged` event, if you specify a field that is not defined in the provided view, an error will be shown."
- [UI Events: General Information](https://github.com/Acumatica/Acumatica-AI-Resources/blob/2026R1/Documentation/DeveloperGuide/UIDev_HandlingEvents_GeneralInfo.md): handlers are marked "for a specified view or field".

## Turning it off

Once, above the offending line: `// muilint-disable-next-line AISI0033`. For the whole file: `// muilint-disable AISI0033`. For a
whole folder, in `.editorconfig`:

```ini
[*.ts]
dotnet_diagnostic.AISI0033.severity = none
```
